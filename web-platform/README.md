# 钢丝绳漏磁在线标注与检测平台

基于2026-10-14同伴版引擎增加的私有课题组工作区。当前为首版待部署程序；提供 Docker 配置并不表示已经上线，也不表示已验证云端性能。

## 使用流程

1. 输入课题组口令登录，上传三轴32通道CSV。
2. 在X/Y/Z图上拖动框选时间和环周通道范围；可放大区间、编辑原始行号、通道范围、类型及备注。
3. 保存标注版本。一个框对应一个缺陷事件，不要在不同轴重复框选同一物理缺陷。`ALL`可表示该框作为跨轴事件查看，不表示通道物理安装方向已经标定。
4. 选择固定检测、规则自适应、统一多模态智能体或TFO工具，提交后台任务。
5. 查看预测和证据图；确认整条记录已完整复核后，对照指定的已保存标注版本评估。

首版采用课题组共用口令，不提供独立用户角色或可靠的个人身份审计。标注者是自行填写的署名。每次保存产生不可覆盖的版本，冲突返回409，防止其他人编辑被静默覆盖。原始文件不可经界面删除或改写。

## 数据与评估约定

- CSV含`mag_1x`…`mag_32x`、y、z共96个有限数值列；512–100000行，默认最大64MB。
- 继承引擎采用名义500Hz，因此当前仅接受用户确认的500Hz数据；其他采样率需要算法适配，不能只修改显示单位。
- 标注索引从0开始，首尾包含；通道从1至32。可导出CSV，保留`label,start_row_idx,end_row_idx`兼容列及空间、类型和版本字段。
- 原始时间戳异常会提示；无同步位置表时不输出米制长度。
- 标注保存在数据库独立表中，推理引擎的数据清单没有标注路径。完成预测后才执行评分；评分保存预测哈希和完整标注快照。
- 当前评分只覆盖时间区间IoU≥0.3/0.5/0.7，主指标0.5，一对一匹配；另给采样点指标。通道和类型标注为后续空间检测研究保留，不伪造空间或分类准确率。
- 完整复核确认表示未标注区域按正常处理。候选仍需人工确认；原有模型和滤波方法不因此获得性能保证。

## 云端结构

`GitHub代码仓库 → 一台Python/Docker服务（网页+API+串行任务） → 持久磁盘（CSV+SQLite+标注版本+预测和证据）`

GitHub Pages不能运行这个Python后端。推荐使用后端同时提供网页，避免跨站Cookie及跨域上传问题。若需要GitHub Pages入口，可放一个公开导航页链接到实际平台，不在导航页放密钥或数据。

必须挂载持久磁盘至`/var/lib/mfl`，或用`MFL_STORAGE_DIR`指定其他持久目录。不要将真实采集数据保存在免费服务的临时文件系统。当前单机SQLite架构只运行一个服务实例；一次处理一个任务，最多排队8个，避免并发算法耗尽内存。服务重启会将未完成任务标记为interrupted，已保存标注和完成结果不受影响，不自动重复付费模型调用。

## 部署

在云服务器或支持Docker与持久磁盘的托管服务上部署。先准备HTTPS域名或托管平台提供的HTTPS地址，在Secrets/服务器私有`.env`配置：

- `MFL_PLATFORM_PASSWORD`：至少12字符的组内口令。
- `MFL_SESSION_SECRET`：至少32字符的随机值；更换后旧登录失效。
- `MFL_PUBLIC_URL`：实际HTTPS访问地址，末尾不带斜杠，用于来源校验。
- `MFL_COOKIE_SECURE=true`：公网部署必须保留。
- `MFL_STORAGE_DIR=/var/lib/mfl`，`PORT=8080`。
- 可选模型环境变量：`MFL_API_BASE`、`MFL_MODEL`、`MFL_API_KEY`。统一模式要求图像输入和工具调用；不提供云端密钥时仍可使用本机规则算法（在服务器运行）。

Docker服务由HTTPS反向代理转发至8080；`compose.yaml`将端口仅绑定服务器回环地址。托管服务应由其TLS代理接入容器，不需要直接公开未加密端口。Docker镜像内不含数据、原API配置或Windows加密文件。

云服务首次部署、持久磁盘挂载、TLS接入、重启持久性、备份与恢复都需要在目标账号上验收后才能正式使用。先备份整个持久存储目录；SQLite运行中请用SQLite backup API生成数据库备份，并在上传/任务停止后复制其余目录，避免只复制主数据库文件漏掉WAL。

## 本机开发和测试（部署人员使用）

安装`requirements.txt`。设置上述口令、密钥和存储目录；只在本机开发时可设`MFL_COOKIE_SECURE=false`及`MFL_PUBLIC_URL=http://127.0.0.1:8080`，运行`python platform_server.py`。

测试不会调用真实模型：`python -m unittest discover -s tests -v`。

用户上线后只需浏览器，不需要在个人电脑安装Python或启动服务。

不要双击`web/index.html`登录。`file://`只打开静态文件，没有登录、上传或检测后端；出现Failed to fetch通常应先核对访问网址与服务是否在线。本机演示使用`http://127.0.0.1:8088/`（需启动独立预览服务），正常开发默认8080；正式使用应打开实际云端HTTPS地址。

## 已知边界

首版未包含独立账号、管理员角色、团队隔离、标注任务分配、审批流程、完整备份调度、任意采集格式适配、位置表上传、跨轴事件合并、候选转标注按钮或数据集批量评估。先验证一条数据的上传—标注—检测—评分链路；这些扩展应按真实使用需要继续实现。
